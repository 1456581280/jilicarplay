# GitHub 正式版更新

更新源固定为 https://github.com/1456581280/jilicarplay 。所有者将仓库公开后，应用无需令牌即可读取正式 Release。不要把 GitHub 私人访问令牌打进 APK。

## 后续发布步骤

1. 在 `mobile/build.gradle.kts` 同时递增 `versionCode` 与 `versionName`。例如从 41 / 0.2.15 改为 42 / 0.2.16。
2. 使用之前保存的同一个 Android 签名密钥构建 release APK；保持包名不变。
3. 在此仓库发布一个非草稿、非预发布的正式 Release，标签格式为 `v0.2.16`。
4. 将安装包命名为 `JiliCarPlay-0.2.16.apk`，作为该 Release 的附件上传，并设为 Latest。GitHub 为附件提供 SHA-256 digest。
5. 仅上传源码、上传到仓库文件区，或勾选 Pre-release，不会触发本应用的正式版本提示。

现有 GitHub Actions release 流程也使用上述附件命名；自动签名发布仍需要已有文档所列的签名和认证 secrets。未配置 secrets 时，CI 只生成不带 CarPlay 认证资源的测试包，不能作为正式更新附件。

## 应用行为

- 打开应用或返回首页且没有 CarPlay 会话时自动检查，成功检查间隔 6 小时；网络失败至少间隔 15 分钟。无网络、私有仓库、GitHub 不可达时不弹出自动错误。
- 点击首页“正式版 · 版本号 · 检查更新”可立即手动检查。
- 新版本先询问是否下载；“稍后”对同版本推迟 24 小时。不会静默下载或静默安装。
- 下载带进度和取消按钮；完成后核对文件大小、SHA-256、包名、递增版本码和安装签名，再请求 Android 安装确认。必要时由系统引导用户授权“允许安装未知应用”。
- 更新只发出 GET 请求读取 GitHub 元数据和安装包，不包含车辆、诊断日志、手机配对或车机硬件信息。没有上传、持久化任务或后台遥测队列。
- 调试包不自动检查正式版，因为包名和签名不同。

这属于 APK 版本更新；运行时代码替换和绕过 Android 安装确认不在本实现内。
