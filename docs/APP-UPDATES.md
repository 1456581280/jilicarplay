## 后续发布

1. 同时递增 `mobile/build.gradle.kts` 中的 `versionCode` 和 `versionName`，保持包名及签名密钥不变。
2. 使用同一签名密钥和已有本地认证资源构建正式 APK，例如 `JiliCarPlay-0.2.17.apk`。
3. 将 APK 上传到上述固定文件夹。应用按文件名中的三段数字版本号比较，忽略广告、其他应用、没有版本号的文件和预发布文件。可保留旧安装包。
4. 在发布前更新飞书文档正文，建议最新版本的日期、版本号和更新内容放在最上方。应用直接读取公开正文，不要求用户登录飞书。

## 用户体验

- 每次打开或从后台回到应用都会自动检查，没有 6 小时缓存或“跳过后 24 小时不检查”的限制。无更新时静默。
- 首页与更新相关的内容只保留“检查更新”；版本号和 GitHub 地址已移除。手动检查会提示结果。
- 检查失败、离线、选择“暂不更新”都不影响既有功能；无强制更新、静默安装或到期禁用。
- 发现新版本先询问。确认后在应用内打开蓝奏云下载页；若服务要求验证，由用户手动完成。不会跳到外部浏览器。
- 获取安装包后显示下载进度并支持取消，核对大小、包名、递增版本码、版本名称和安装签名，最后由用户确认安装。蓝奏云没有发布 SHA-256 元数据，完整性由 APK 签名及 Android 安装器校验。
- 首次运行新版本时，读取飞书正文并显示原生、可滚动的更新日志弹窗；每个已安装版本只显示一次。读取失败时保留待显示状态，下次打开重试。不会展示网页导航、评论、登录页或打开浏览器。
- 检查结果在窗口获得焦点后显示；正在投屏时暂缓弹窗。更新操作不发送车辆、手机、日志或设备标识。

第三方服务若调整网页结构或下载域名，自动检查会提示暂不可用而保留现有功能。联网冒烟验证：构建 `:common:assembleDebugAndroidTest` 后运行 `adb shell am instrument -w -e updates true com.shilapi.xcertplay.host.test/com.shilapi.xcertplay.HtmlHomeRenderInstrumentation`。
